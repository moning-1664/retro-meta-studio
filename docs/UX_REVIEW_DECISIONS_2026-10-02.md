# UX 리뷰 검토와 확정 기준

## 사용자 확정 사항

- 보관소 이름은 Archive로 통일한다. 보관소를 가리키는 “마스터”는 사용하지 않는다. 실제 콘솔 이름인 Master System은 이 규칙의 대상이 아니다.
- 온라인 스크랩과 다른 Collection/Archive에서 가져오기는 구분한다.
- 상세 패널의 요약 카드를 유지한다.
- 작은 글씨의 8~9px 혼용은 9px로 통일한다. 기존 본문·입력값까지 9px로 줄이지 않는다.
- 버전은 앱 이름 영역의 우측 아래에 더 작게 배치하고 앱 타이틀은 키운다.
- 기존 메뉴의 명칭과 순서를 먼저 다듬는다. 메뉴를 합치거나 하위 메뉴를 늘리는 일은 별도 판단한다.

## 외부 리뷰에 대한 반박 및 유보

1. **일부 지적은 이전 코드 기준이다.** 커밋 `7854117`에는 Slate 기본 테마, Pearl/Carbon/Sand/Aqua 이름, 한국어 내비게이션·설정 제목, 콘솔별 토글 장식 색 제거가 들어 있다. SYSTEMS/All Games 등과 SFC 토글 색 문제를 그대로 현재 문제로 취급하지 않는다.
2. **번역률 숫자는 재검증이 필요하다.** 1,002개 중 338개라는 집계는 대상 커밋·중복 제거·주석 제외·동적 문자열 처리·기존 패턴 번역 포함 여부를 확인하기 전에는 현재 번역률로 확정하지 않는다. 실제 언어 전환 화면과 누락 검사를 함께 사용한다.
3. **Storage를 모두 기기로 바꾸면 부정확하다.** 로컬 폴더와 네트워크 저장소도 포함한다. “내 목록/마스터/기기”라는 용어 체계를 자동 적용하지 않는다. Archive 명칭은 위 확정 사항을 따른다.
4. **스크랩과 가져오기를 합치지 않는다.** 온라인 서비스 조회와 보유 데이터 재사용은 출처와 동작이 다르다. 명칭으로 차이를 드러낸다.
5. **중복 정보가 있다는 이유로 요약 카드를 삭제하지 않는다.** 커버와 핵심 정보를 빠르게 확인하는 역할을 유지하고, 필요하면 카드 안의 중복 정보와 순서를 조정한다.
6. **작은 글씨를 일괄 11~12px로 올리지 않는다.** 정보 밀집도 요구와 충돌한다. 작은 라벨은 9px로 정리하고 본문·입력값은 기존 크기를 유지한다.
7. **모든 작업에 실행 취소 안내를 붙이지 않는다.** 실제로 복구 가능한 작업에만 표시한다. 삭제·이동·이름 변경별 지원 범위를 확인한다.
8. **저장된 필터를 구현하지 않는다.** 사용자가 앞서 제외했다. 첫 실행 위저드도 후순위이며 빈 화면의 짧은 다음 행동 안내를 먼저 개선한다.
9. **1000×640 겹침은 재현 후 판단한다.** 수평 스크롤을 사용하는 넓은 목록과 실제 컨트롤 겹침을 구분한다. 목업 Chromium 캡처를 WebView2 실사용 검증으로 대신하지 않는다.
10. **앱의 개성 부족은 제품 판단이다.** 기본 테마의 절제된 색을 기능 결함으로 취급하지 않는다. 시스템 배너는 이번 범위에서 제외한다.

## 수용한 후속 개선 방향

1. 한국어 UI의 용어와 남은 영어 혼용을 정리한다.
2. 새 문구부터 번역 키 ID와 변수 방식을 적용하고 번역 누락 검사를 도입한다. 기존 번역을 한 번에 전면 교체하지 않는다.
3. 좁은 창의 실제 겹침을 수정하고, 빈 Archive와 검색 결과 없음의 안내를 구분한다.
4. F1 단축키 도움말을 제공한다.
5. 대시보드의 누락 항목에서 해당 목록으로 이동하는 기능은 현재 연결 여부부터 확인한다.

위 후속 항목은 진행 방향이며 이 문서 작성 시점의 구현 완료 목록이 아니다.

## 이번 변경 검증

- 타이틀 18px, 버전 9px 우측 아래 배치와 작은 라벨 정리를 검증했다.
- 관련 UI 테스트 33개 통과. 너비 1000/1280px, 배율 100/130%의 4개 조합에서 타이틀·버전 영역 넘침과 겹침 검사를 통과했고 캡처를 확인했다.
- 전체 UI 테스트는 644개 중 643개 통과, 붙여넣기 하위 메뉴 테스트 1개 실패. 실패한 테스트의 단독 5회 반복은 모두 통과했으나 전체 실행 실패의 원인은 확정하지 못했다. 전체 통과로 기록하지 않는다.
- app.js 문법 검사와 git diff --check 통과.
- Chromium 목업 검증이며 실제 WebView2, NAS, ScreenScraper 서비스 동작 검증은 아니다.

### 메뉴 이벤트 후속 검증

- 앞서 실패한 하위 메뉴 테스트는 4개 워커로 30회 반복해 모두 통과했다. 원래 실패의 직접 원인은 확정하지 않았다.
- 별도 재현: 같은 이벤트 작업 안에서 메뉴 열기 → Escape → 다시 열기를 수행하면, 이전 메뉴가 예약했던 mousedown 등록이 뒤늦게 실행된다. 새 메뉴 안을 눌러도 이전 핸들러가 바깥 클릭으로 판단해 새 메뉴를 닫았다. 추가 테스트는 수정 전 실패했다.
- 메뉴 정리 시 예약된 등록 타이머도 취소하도록 수정했다. 복사·붙여넣기 테스트 23개 통과, 전체 UI 회귀 테스트 645개 통과(3.5분).
- 이 재현으로 확인된 결함과 앞선 간헐 실패가 같은 원인이라고 단정하지 않는다.

# Phase 7.8 — ROM만 있는 Collection

**요약.** 스크래핑을 한 번도 안 한 컬렉션 — ROM 폴더만 있고 gamelist.xml이 없는 상태 —
을 열 수 있게 했다. 사용자의 실제 `C:\Games\ROMs`가 정확히 그 모습이었고, **그동안은
Collection으로 열리지도 않았다**(Adapter 4종 전부 confidence 0.0).

이제 그 트리에서 **25개 시스템 3,164게임**이 0.7초 만에 열린다.

파이썬 371개(신규 15개), Playwright 62개(신규 5개) 전부 통과.

---

## 흐름

```
ROM만 있는 폴더 추가
  ↓  "메타데이터가 없습니다. 만들까요?"   ← 불러오기 전에 묻는다
  ├─ 나중에      → 그대로 열린다. Gamelist에 파일명이 제목 자리에 뜬다.
  │                항목을 고쳐 저장하면 그때 gamelist.xml이 만들어진다.
  └─ 만들기      → ROM 목록만 담은 gamelist.xml을 System마다 만든다.
```

**묻는 시점이 "불러오기 전"인 이유**: 스캔이 끝난 뒤에 물으면 사용자는 이미 "메타데이터
없는 목록"을 본 뒤라, 그 안내가 무엇을 정하는 건지 알기 어렵다.

---

## 고친 것 / 만든 것

### ① Detection — ROM만 있어도 Collection이다

ES-DE Adapter의 `detect()`가 `gamelists/`도 `downloaded_media/`도 없을 때
**ROM이 든 System 폴더**를 찾아본다. 찾으면 `confidence 0.3`으로 받아들인다.

확신을 낮게 주는 이유는 정직해서다 — 어느 Frontend의 ROM 폴더든 이 모양이라
"ES-DE라고 확신"할 근거가 없다. 그래도 사용자가 시작은 할 수 있어야 한다.

**폴더가 있다고 전부 System으로 잡지는 않는다.** ROM처럼 생긴 파일이 하나라도 있어야
한다 — 안 그러면 `themes`나 사용자의 잡동사니 폴더까지 딸려 들어온다.

### ② 열기만 해서는 아무것도 쓰지 않는다

열어 보기만 했는데 사용자 폴더에 `gamelists/`가 생기면 안 된다. 테스트로 고정했다.

### ③ 편집해서 저장하면 그때 만들어진다

이건 이미 되고 있었다(`write_index`가 파일이 없으면 만든다). 회귀 테스트만 더했다 —
**하나를 고쳤다고 나머지까지 멋대로 써 넣지 않는 것**까지 포함해서.

### ④ 미리 만들어 두기 (`app/metadata/service.py`)

- `status()` — System별로 gamelist가 있는지, ROM은 몇 개인지. **ROM이 있는데 gamelist가
  없는** System만 `missing`에 담는다(빈 폴더에 만들어 줄 이유는 없다).
- `generate()` — ROM 목록만 담은 gamelist를 쓴다.

두 가지를 하지 않는다.

- **추측해서 채우지 않는다.** `<name>`은 파일명 stem 그대로고 장르·출시일은 비운다.
  우리는 스크래퍼가 아니고, 잘못 채운 값은 사용자가 일일이 지워야 한다.
- **이미 있는 gamelist는 건드리지 않는다.** 비어 있는 gamelist조차 사용자가 의도해서
  만든 것일 수 있다. 덮어쓰기 사고를 원천적으로 막는다.

실제 폴더에는 **아무것도 쓰지 않았다** — 상태만 확인했다.

## 기존 UI 스펙 2개를 함께 고쳤다

Collection을 새로 추가하면 이제 안내가 한 번 뜨므로, "추가 → 곧바로 탭이 열린다"를
전제하던 스펙 두 개가 깨졌다. 의도한 동작 변경이라 스펙을 새 흐름에 맞췄다.

ROM은 이제 보이지만 그 gamelist는 못 읽는다 — 다음 후보다.

# Phase 7.2 — Adapter 간 변환(Convert) UI

**요약.** 스펙 §53의 Convert를 붙였다. 새로 만든 코드는 사실상 **미리보기뿐**이다 —
변환 자체는 이미 있는 것들(공통 모델 + target Adapter + Plan)의 조합이기 때문이다.

파이썬 305개(신규 13개), Playwright 51개(신규 6개) 전부 통과.

---

## 1. 변환에 새 실행 경로를 만들지 않았다

```
source cache의 row ──(공통 모델)──> builder.plan_add ──> Plan ──> Apply
                                                                  └─ target Adapter가
                                                                     자기 포맷으로 쓴다
```

공통 모델을 거치는 순간 "어느 Frontend에서 왔는지"는 사라지고, 쓸 때는 target Adapter가
자기 포맷을 책임진다. 붙여넣기(`paste`)와 **같은 `builder.plan_add`를 쓴다** — 목적지 충돌
판정, 용량 계산, 원본이 사라진 항목 건너뛰기가 전부 거기 이미 있다.

그래서 Convert는 Plan 계약을 그대로 따른다: **Plan 단계에서는 아무 파일도 바뀌지 않고**,
확정은 언제나 Apply의 몫이다. 원본 Collection은 읽기만 한다(§53 "원본 보존").

---

## 2. 미리보기 — 무엇을 잃는지 정직하게 센다

Frontend 간 변환은 **반드시 무언가를 잃는다**(§50-51). 그걸 실행 전에 보여주지 않으면
사용자는 "이 변환을 해도 되는가"를 판단할 수 없다.

```
Master Library (ES-DE)  →  Android ES-DE (Pegasus)

Games                 1,284
Metadata              1,284
Media                 4,821
─────────────────────────────
Unsupported fields       37     ← region (Pegasus 포맷에 자리 없음)
Unsupported media        96     ← Pegasus가 다루지 않는 종류
Frontend-specific       112     ← 원본 Frontend 고유 값
```

넘어가는 것과 잃는 것을 **표 안에서 갈라 놓았다.** 한 줄로 섞으면 숫자가 크다는 것만
보이고 무엇이 위험한지는 안 보인다.

### 세는 규칙에서 신경 쓴 것

- **값이 비어 있으면 세지 않는다.** `region` 태그가 있어도 값이 빈 문자열이면 잃을 것이
  없다. 겁주는 숫자를 만들지 않기 위함이다.
- **어느 필드인지 이름까지 준다**(`unsupportedFieldNames`). 숫자만 보여주면 사용자가
  무엇을 잃는지 알 수 없다. UI는 이걸 툴팁으로 보여준다.
- **필드와 media는 별개의 축이다.** EmulationStation은 공통 필드 9개를 전부 담을 수 있어
  `unsupportedFields`가 0이지만, `3dboxes`에 해당하는 태그가 없어 그 media는 여전히
  못 받는다. 두 숫자를 하나로 합치면 이 구분이 사라진다 — 테스트로 고정했다.

---

## 3. Adapter 계약에 `supported_fields`를 더했다

미리보기가 "이 포맷에 자리가 없는 필드"를 세려면, 각 Adapter가 **자기 포맷의 한계를 스스로
알려야 한다.** 기본값은 공통 필드 9개 전부이고, Pegasus만 `region`을 뺀다
(`metadata.pegasus.txt`에 해당 키가 없다).

이 값을 서비스 쪽에 하드코딩하지 않은 이유는 명확하다 — 그러면 Adapter를 추가할 때마다
Convert 서비스를 함께 고쳐야 하고, 그건 "Adapter가 포맷 지식을 독점한다"는 원칙을 깨는
것이다.

---

## 4. UI

탭 우클릭 → `Convert` → 대상 Collection 선택 → 미리보기 → `Plan에 올리기`.

- 대상 목록에 **자기 자신은 없다.**
- Plan에 올린 뒤 **대상 Collection 탭으로 데려간다.** 그러지 않으면 사용자는 아무 일도
  안 일어난 것처럼 느낀다.
- 토스트가 "Apply를 눌러야 실제로 반영됩니다"를 명시한다 — Plan에 올린 것과 반영된 것을
  혼동하면 안 된다.

---

## 5. 남은 것

- **부분 변환**(System 하나만, 선택 항목만). 서비스는 이미 `systems=` 인자를 받게 해
  두었지만 UI에는 노출하지 않았다. 전체 변환이 기본 시나리오라 먼저 그것만 붙였다.
- Phase 7.1에서 적어 둔 `write_index()`의 항목별 호출(O(n²))은 그대로다. Convert가
  대량 항목을 Plan에 올리는 경로를 만들었으므로 **이 문제가 실제로 드러나기 쉬워졌다** —
  다음에 다룰 후보로 우선순위가 올라갔다.

# Phase 7.9 — ES-DE 메타데이터 처리 검증: **읽는 것만 봤더니 쓰는 쪽이 새고 있었다**

**요약.** Phase 7.7에서 실제 백업 26개 gamelist를 전부 읽게 만들었다. 이번에는
**다시 쓰는 쪽**을 검증했고, 저장 한 번에 사용자 설정이 사라지는 결함을 찾았다.

| | 고치기 전 | 고친 후 |
|---|---|---|
| 저장 후 `<alternativeEmulator>` | **9개 시스템에서 사라짐** | 그대로 남음 |
| 저장 후 새로 생기는 태그 | 게임마다 빈 `<region/>` (1,558개) | 없음 |
| 저장 후 달라지는 값 | `rating` 1,119개 (`0.9`→`0.90`) | 없음 |
| **파일 단위 차이** | 27개 파일 중 27개가 달라짐 | **0개** |

파이썬 380개(신규 9개), Playwright 62개 전부 통과.

---

## 왜 지금까지 못 봤나 — round-trip 테스트의 사각지대

Phase 7.7 직후 실제 자료 26개 gamelist로 round-trip을 돌려 **1,539개 항목, 필드
유실 0, frontend_raw 유실 0**을 확인했었다. 그런데 그 확인은 이렇게 생겼다.

```
읽기 -> 쓰기 -> 다시 읽기 -> 처음 읽은 것과 비교
```

**전부 "우리가 읽는 것"끼리의 비교다.** 우리가 아예 읽지 않는 부분이 사라지면 양쪽
모두에서 똑같이 없으므로 영원히 통과한다. 그래서 이번에는 기준을 바꿨다.

```
읽기 -> 쓰기 -> **파일 자체**를 처음 파일과 비교 (태그 개수 / (path,tag)별 값)
```

바꾸자마자 세 가지가 한꺼번에 나왔다.

---

## ① `<alternativeEmulator>` 유실 — Phase 7.7이 만든 결함

ES-DE 3.x는 `<gameList>` **앞에 형제로** 이 요소를 쓴다. 사용자가 그 System에 대해
고른 에뮬레이터다.

```xml
<?xml version="1.0"?>
<alternativeEmulator>
    <label>Snes9x 2010</label>
</alternativeEmulator>
<gameList>
```

Phase 7.7의 `_parse_multi_root()`는 임시 루트로 감싸 읽은 뒤 **`<gameList>`만 꺼내
돌려줬다.** 읽기에는 그것으로 충분했지만, `write_index()`가 그 트리를 그대로 다시
쓰면서 **앞에 있던 것이 통째로 날아갔다.** 실제 백업 26개 중 9개가 이 형태다.

읽을 수 있게 만든 변경이 곧바로 쓰기 쪽 유실을 만든 셈이다 — 읽기와 쓰기가 같은
파서를 공유하면 한쪽만 보고 끝낼 수 없다.

→ `_read_document()`가 `(gameList 루트, 앞 원문, 뒤 원문)`을 함께 돌려주고,
`_write_document()`가 그 원문을 있던 자리에 되돌려 놓는다. **우리가 해석하지 않는
부분은 해석하지 않은 채로** 문자열 그대로 들고 있는다 — 파싱해서 다시 만들면 우리가
모르는 형태를 우리 모양으로 바꿔 쓰게 된다.

`write_index()`와 `remove_entries()` 둘 다 이 경로를 쓴다.

## ② 없던 `<region>`이 게임마다 생김

`_set()`이 값이 비어 있어도 태그를 만들었다. ES-DE가 읽는 값은 달라지지 않지만
1,558개 항목에 전부 `<region/>`이 붙는다. 사용자가 파일을 열어 보거나 버전 관리에
넣어 두면 그냥 잡음이다.

→ **없던 태그를 빈 값으로 새로 만들지 않는다.** 반대로 **이미 있던 값을 비우는 것은
그대로 한다** — 사용자가 지운 값은 지워져야 하고, 그건 "안 쓰는 것"과 다르다.

## ③ `rating` 형식이 우리 것으로 바뀜

`f"{v/5:.2f}"`로 고정 폭이라 `0.9`가 `0.90`이 됐다. 값은 같다. 그런데 실제 백업의
rating은 전부 `0.8`/`0.9`/`1` 꼴이었고(2자리로 쓴 것은 하나도 없다), 저장할 때마다
1,119줄이 뜻 없이 달라진다.

→ 필요한 자리만 쓴다. `0.9`는 `0.9`, 만점은 `1`.

## 검증 — 실제 자료, 복사본에만

```
gamelist 27개 / 게임 1,558개 / 값 14,282개
  태그가 달라진 파일   0개
  값이 달라진 필드     0개
  원본 무결성          그대로 (sha256 전/후 동일)
```

원본은 읽기만 한다. 검증 스크립트가 시작할 때와 끝날 때 원본 `gamelists/` 전체의
sha256을 찍어 그것을 증명한다. 쓰기는 전부 임시 폴더의 복사본에서 일어난다.

## 회귀 테스트

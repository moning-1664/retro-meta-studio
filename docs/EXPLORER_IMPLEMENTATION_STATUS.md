# 탐색기 모델 구현 상태

2026-10-01 · 브랜치 `codex/simplify-copy-paste-archive`

## 구현한 범위

- 붙여넣기 / 채우기 / 교체하기가 처리 정책을 결정한다. 별도 모드 토글이나 대기 Plan의 Apply/Cancel은 표시하지 않는다.
- 일반·멀티 붙여넣기는 같은 System과 전체 ROM 파일명으로 충돌을 판단한다. 한 게임을 다른 행에 명시적으로 붙이면 대상 ROM을 유지하고 메타데이터·미디어를 처리한다.
- 독립 미리보기 → 기존/대상 비교 → 충돌 결정 → background 즉시 실행. 취소한 미리보기는 파일을 변경하지 않는다.
- Collection의 붙여넣기·잘라내기·삭제·메타데이터 저장·이름 변경에 작업 기록과 Undo/Redo를 제공한다. 이동은 대상 복사가 성공한 뒤 원본을 제거한다.
- Archive의 붙여넣기·수집·일반 편집·Revision 선택·보관 파일 삭제·이름 변경도 DB, frontend 인덱스, 변경 파일을 같은 복구 기록에 묶는다.
- Archive↔Collection 잘라내기는 양쪽 파일과 인덱스를 한 기록으로 관리한다. Undo/Redo와 재시작 복구 후 관련 Collection 캐시도 다시 읽는다. 다른 System으로 이동하거나 같은 물리 파일을 참조하는 이동은 거부한다.
- Archive 전용 ROM 이름 변경은 파일을 복사하지 않는다. 외부 Collection에 연결된 ROM은 Archive에서 삭제·이동·이름 변경하지 않는다.
- Archive ROM 교체는 같은 볼륨의 임시 파일에 한 번 복사하고 원본 상태·크기를 확인한 뒤 기존 ROM을 백업으로 이동하고 게시한다. 미디어는 크기 비교를 사용하며 콘텐츠 해시를 계산하지 않는다.
- Archive 파일 복사의 임시 경로를 기록한다. 확인 가능한 중단을 복구할 때 해당 임시 파일도 정리한다. 불확실한 상태나 외부 변경은 자동 복원을 거부하고 백업을 보존한다.
- 공유 Archive의 편집 잠금, DB digest CAS, 충돌 시 양쪽 버전 보존을 유지한다. NAS 경로도 Archive journal을 사용한다. 기록·작은 DB 백업은 PC 로컬, 이동한 ROM 백업은 원래 파일 옆에 둔다.
- Ctrl+Z / Ctrl+Y, 우클릭 실행 취소 / 다시 실행, 작업 기록 목록·백업 용량·명시적 백업 삭제를 제공한다. 복구 중인 기록은 삭제하지 않는다. 실패 로그는 기존 `.log`로 남긴다.
- 복구 sidecar는 모든 frontend의 ROM 스캔에서 제외한다. 기존 캐시를 정리하기 위해 스캔 버전을 올렸으므로 최초 한 번 재색인이 필요하다.
- DAT/listxml 제목 힌트, 단일 ROM ZIP의 중앙 디렉토리 CRC/크기, 제한된 이름 변형 검색과 실패 캐시를 유지한다. 후보는 cover/screenshot 미리보기만 사용하고 선택 적용 시 필요한 파일을 다운로드한다.
- 모달 뒤의 목록에 변경 단축키가 전달되지 않으며, 사용자 화면에 남아 있던 Plan 안내와 미사용 Auto Plan 상태를 정리했다.

## 내부 호환과 제외 범위

기존 `app/plan`의 검증·파일 적용 엔진과 프로그램용 호환 API는 유지한다. 사용자에게 대기 Plan 사용을 요구하지 않는다. 이를 삭제하면 기존 검증과 파일 작업 엔진을 재작성해야 하므로 사용자 화면 제거와 구분한다.

기기 프로필·용량 추천·1G1R·저장된 필터는 구현하지 않는다. 번역·ADB·첫 실행 위저드는 후순위다.

Collection 일반 작업의 자동 Undo는 로컬 파일시스템 범위다. MTP 및 일반 네트워크 Collection의 자동 Undo는 보장하지 않는다. Archive와 MTP 사이의 잘라내기는 지원하지 않으며 복사를 사용한다.

## 검증과 남은 실사용 확인

- 전체 Python 회귀 테스트 및 실패 주입: 결과는 아래 실행 기록으로 갱신한다.
- UI 목업은 즉시 작업·충돌·Undo/Redo·작업 기록·기존 화면을 검증한다. 제거된 Plan 배지/대기 화면 테스트는 현재 흐름으로 교체했다.
- **실제 두 PC의 NAS 잠금 인계·공유 변경·네트워크 단절·배포 EXE 강제 종료는 아직 직접 검증하지 않았다.** 로컬 파일과 테스트 대역 결과를 실제 NAS 통과로 표시하지 않는다.
- `debug.log`는 사용자의 파일이므로 커밋하지 않는다.

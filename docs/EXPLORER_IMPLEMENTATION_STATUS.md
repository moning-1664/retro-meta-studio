# 탐색기 모델 구현 상태

2026-09-30. 작업 브랜치: `codex/simplify-copy-paste-archive`.
완료된 기능과 남은 작업을 분리한 기록이다. 전체 P0–P6 완료 판정은 아직 아니다.
번역·ADB·첫 실행 위저드는 후순위로 유지한다.

## 반영된 동작

- 붙여넣기 / 채우기 / 교체하기를 직접 선택한다. 별도 모드 토글과 멀티 선택 시 자동 모드 변경을 제거했다.
- 일반 붙여넣기는 같은 System + 전체 ROM 파일명으로 충돌을 판정한다. Windows 파일명 대소문자는 구분하지 않는다.
- 게임 하나를 명시적 다른 게임에 붙이면 대상 ROM을 유지하고 메타데이터·미디어를 처리한다.
- Collection 붙여넣기는 독립 미리보기 → 게임별 충돌 결정 → background 실행이다. 기존 Plan 항목을 섞지 않는다.
- 로컬 ROM 교체는 같은 볼륨의 임시 파일에 한 번 복사하고 크기를 확인한 뒤 원본을 백업으로 이동한다.
- 로컬 붙여넣기·삭제·메타데이터 저장은 작업 기록과 인덱스 백업을 남긴다. 중단 복구와 Ctrl+Z를 지원한다.
- 작업 후 외부에서 바뀐 파일은 실행 취소로 덮어쓰지 않는다. 연속 실행 취소 시 인덱스 복원으로 바뀐 파일 ID를 보정한다.
- 네트워크·MTP에는 로컬 실행 취소를 보장하지 않으며 파일 작업 전에 확인한다.
- Archive 붙여넣기도 같은 충돌 UI에서 독립 실행한다. 실행 전 대상 상태와 원본 파일의 크기·수정시각·파일 ID를 확인한다.
- Archive 수동 편집의 frontend 반영 뒤 공유 DB도 게시한다. DB digest CAS와 충돌 시 양쪽 백업은 유지한다.
- DAT/listxml 가져오기는 공식 제목을 검색 힌트로 제공한다. ZIP은 단일 파일일 때 중앙 디렉토리의 크기·CRC를 읽는다. 모호한 CRC는 정확한 매칭으로 취급하지 않는다.
- 실패한 이름 조회는 짧은 캐시를 사용하며 강제 재검색으로 우회할 수 있다. 추가 쿼리 수는 제한한다.
- 모달 뒤의 목록에 복사·붙여넣기·삭제·새로고침 단축키가 전달되지 않는다. Ctrl+F는 목록 검색을 선택한다.

- 로컬 Collection의 Ctrl+X 이동은 대상 복사가 성공한 뒤 원본을 제거한다. 양쪽 인덱스·파일을 같은 작업 기록으로 복원한다.
- F2는 ROM과 해당 게임의 전용 미디어 파일을 복사 없이 이름 변경한다. 쓰기 실패 시 원래 파일명과 인덱스로 복원한다.
- MTP 저장 실패는 오류로 전달하며 성공으로 표시하지 않는다.

## 남은 구현

1. Archive의 잘라내기·이름 변경과 네트워크 이동 복구. 로컬 Collection의 잘라내기·이름 변경·Undo는 구현했다.
2. Archive의 DB·frontend·내부 파일을 함께 복원하는 실행 취소. 현재 Archive 붙여넣기는 파일 전체 복원을 보장하지 않는다.
3. 실제 두 PC에서 공유 Archive 편집 잠금·명시적 인계 검증. 파일 기반 잠금과 Settings의 상태·중단 잠금 해제는 구현했으며 DB CAS는 별도로 유지한다.
4. 작업 기록 목록·복구 실패 안내·백업 보관 공간 관리·Redo.
기기 프로필·용량 추천·1G1R·저장된 필터는 사용자 결정으로 구현 범위에서 제외한다.
6. 내부 호환 Plan API와 오래된 설명 정리. 사용자 화면의 Apply/Cancel 대기 목록과 Compare·변환·가져오기·미디어 붙여넣기 큐 경로는 제거했다.

## 검증 범위

- Python 전체 테스트 실행과 붙여넣기·삭제·실행 취소 실패 주입 테스트.
- 브라우저 목업의 복사·붙여넣기, System 메뉴, Archive 선택·Revision·설정, Detail 및 Scraper UI 테스트.
- 실제 NAS·MTP·배포 EXE의 성능 및 강제 종료 복구는 위 테스트로 통과 판정하지 않는다.
- `debug.log`는 사용자의 기존 파일로 보존한다.
